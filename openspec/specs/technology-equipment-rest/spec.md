# technology-equipment-rest Specification

## Purpose
Предоставляет tenant-scoped HTTP-контракт для управления справочником оборудования по пути `/api/v1/equipment` и аддитивно расширяет контракт операций технологического процесса полем `equipmentId`.

## Requirements

### Requirement: REST создание, чтение и список оборудования
REST SHALL предоставлять `POST /api/v1/equipment` (201, возвращает представление), `GET /api/v1/equipment/{id}` (200) и `GET /api/v1/equipment` (200, массив представлений).

#### Scenario: Создание и чтение
- **WHEN** клиент отправляет валидные `number`, `name` и `type`
- **THEN** POST возвращает статус 201 с представлением, а GET созданного оборудования возвращает статус 200

#### Scenario: Список
- **WHEN** клиент запрашивает список оборудования
- **THEN** ответ содержит активное оборудование текущей организации, отсортированное по `number`

### Requirement: REST обновление и удаление оборудования
REST SHALL предоставлять `PUT /api/v1/equipment/{id}` (204, без тела) и `DELETE /api/v1/equipment/{id}` (204, мягкое удаление).

#### Scenario: Обновление и удаление
- **WHEN** клиент обновляет оборудование и затем удаляет его
- **THEN** обе операции возвращают 204, а последующее чтение оборудования возвращает 404

### Requirement: REST полное обновление изменяемых полей оборудования
`PUT /api/v1/equipment/{id}` SHALL принимать тело с изменяемыми полями `name` и `type` и SHALL не принимать и не изменять `number`.

#### Scenario: Обновление без номера
- **WHEN** клиент отправляет PUT с телом `{name, type}` без `number`
- **THEN** операция возвращает 204, а `number` оборудования не изменяется

### Requirement: REST ошибки оборудования
REST SHALL возвращать 404 с кодом `not_found` для отсутствующего, удалённого или чужого оборудования, 409 с кодом `duplicate` для дубликата номера в организации и 400 с кодом `bad_request` для ошибок валидации полей оборудования.

#### Scenario: Отсутствующий ресурс
- **WHEN** запрос адресует чужое, удалённое или отсутствующее оборудование
- **THEN** ответ имеет статус 404 и код `not_found`

#### Scenario: Дубликат номера
- **WHEN** создание получает номер, уже занятый активным оборудованием организации
- **THEN** ответ имеет статус 409 и код `duplicate`

#### Scenario: Ошибка валидации
- **WHEN** запрос содержит пустой `number`, `name` или `type`
- **THEN** ответ имеет статус 400 и код `bad_request`

### Requirement: REST tenant-контекст оборудования
REST SHALL определять организацию оборудования только через серверный `OrganizationContext` и SHALL игнорировать клиентский заголовок `X-Organization-Id` и tenant в URL или теле запроса.

#### Scenario: Игнорирование клиентского tenant
- **WHEN** клиент организации A передаёт заголовок `X-Organization-Id` организации B
- **THEN** операция выполняется в контексте организации A, а данные организации B не раскрываются

### Requirement: Оборудование через публичный API technology
Контроллер оборудования SHALL размещаться в модуле `web` и обращаться к оборудованию только через `technology.api` (`EquipmentService`); новых межмодульных зависимостей SHALL не добавляться, а граф модулей SHALL оставаться ацикличным.

#### Scenario: Проверка доступа web к оборудованию
- **WHEN** выполняется `ApplicationModules.verify()`
- **THEN** проверка проходит, обращение `web` к оборудованию направлено в `technology.api`, а циклов в графе нет
