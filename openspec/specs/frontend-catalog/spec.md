# frontend-catalog Specification

## Purpose

Предоставляет пользователю веб-интерфейс для просмотра и управления деталями каталога через существующий REST-контракт ForgeFlow.

## Requirements

### Requirement: Отображение списка деталей
Приложение SHALL отображать детали текущей организации в таблице с колонками номера, названия и даты создания.

#### Scenario: Успешная загрузка списка
- **WHEN** приложение открывает экран каталога и `GET /api/v1/parts` возвращает массив деталей
- **THEN** таблица содержит для каждой детали значения `number`, `name` и `createdAt`

### Requirement: Создание детали
Пользователь SHALL иметь возможность отправить форму с номером и названием детали, после чего приложение SHALL создать деталь через `POST /api/v1/parts`.

#### Scenario: Успешное создание
- **WHEN** пользователь вводит номер и название и отправляет форму, а API возвращает 201 с созданной деталью
- **THEN** приложение отображает созданную деталь в списке и очищает форму

### Requirement: Переименование детали
Пользователь SHALL иметь возможность изменить название существующей детали, а приложение SHALL отправлять новое название на `PUT /api/v1/parts/{id}/name`.

#### Scenario: Успешное переименование
- **WHEN** пользователь подтверждает новое непустое название, а API возвращает 204
- **THEN** приложение отображает новое название у соответствующей детали

### Requirement: Подтверждение удаления детали
Приложение SHALL запрашивать подтверждение перед удалением детали и SHALL удалять её через `DELETE /api/v1/parts/{id}` только после подтверждения.

#### Scenario: Удаление после подтверждения
- **WHEN** пользователь подтверждает удаление, а API возвращает 204
- **THEN** приложение исключает деталь из таблицы

#### Scenario: Отмена удаления
- **WHEN** пользователь отменяет подтверждение удаления
- **THEN** приложение не отправляет запрос `DELETE` и сохраняет деталь в таблице

### Requirement: Отображение ошибок API
Приложение SHALL отображать человекочитаемое сообщение для ошибок API со статусами 400, 404 и 409.

#### Scenario: Дублирующий номер
- **WHEN** операция создания получает 409 с `error` равным `duplicate`
- **THEN** интерфейс сообщает, что деталь с таким номером уже существует

#### Scenario: Некорректные данные
- **WHEN** операция получает 400 с `error` равным `bad_request`
- **THEN** интерфейс отображает сообщение о некорректных данных запроса

#### Scenario: Деталь не найдена
- **WHEN** операция получает 404 с `error` равным `not_found`
- **THEN** интерфейс сообщает, что деталь не найдена

### Requirement: Состояния загрузки каталога
Приложение SHALL отображать состояние загрузки при получении списка и SHALL предотвращать повторную отправку активной операции до получения её результата.

#### Scenario: Загрузка списка
- **WHEN** `GET /api/v1/parts` находится в процессе выполнения
- **THEN** интерфейс отображает индикатор загрузки вместо завершённого результата списка

### Requirement: Визуальное оформление каталога
Интерфейс SHALL использовать светлую тему, таблицу с тонкими границами и визуальную палитру с тёмным графитовым акцентом RAL 7024 и светлой серо-бежевой подложкой RAL 7032.

#### Scenario: Отображение основного экрана
- **WHEN** пользователь открывает экран каталога
- **THEN** шапка или акцентные элементы используют цвет, соответствующий приблизительному `#474A51`, а фоновые подложки — приблизительному `#B8B4A6`
