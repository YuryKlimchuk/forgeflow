# specifications-rest Specification

## Purpose

Предоставляет React-клиенту tenant-scoped HTTP-контракт для просмотра и изменения прямых строк спецификации сборочной единицы и копирования спецификации.

## Requirements

### Requirement: REST чтения спецификации
REST SHALL предоставлять получение строк по `AssemblyId` по маршруту `GET /api/v1/specifications/{assemblyId}/rows` со статусом `200`.

#### Scenario: Список строк
- **WHEN** клиент запрашивает строки активной сборки текущей организации
- **THEN** ответ имеет статус `200` и содержит JSON-массив строк с типом элемента, идентификатором и количеством

### Requirement: REST добавления строки
REST SHALL принимать добавление строки через `POST /api/v1/specifications/{assemblyId}/rows` и SHALL возвращать созданную строку со статусом `201`.

#### Scenario: Добавление детали
- **WHEN** тело содержит допустимый тип элемента, идентификатор и положительное количество
- **THEN** ответ имеет статус `201` и содержит сохранённую строку

### Requirement: REST изменения количества
REST SHALL принимать новое количество через `PUT /api/v1/specifications/{assemblyId}/rows` и SHALL возвращать статус `204` после успешного изменения строки, адресованной ссылкой на элемент.

#### Scenario: Изменение количества
- **WHEN** тело содержит существующую ссылку элемента и положительное количество
- **THEN** строка обновляется, а ответ имеет статус `204`

### Requirement: REST удаления строки
REST SHALL удалять строку через `DELETE /api/v1/specifications/{assemblyId}/rows` и SHALL возвращать статус `204` после успешного удаления, адресованного ссылкой на элемент.

#### Scenario: Удаление строки
- **WHEN** тело содержит ссылку существующей строки
- **THEN** строка больше не возвращается GET-запросом, а ответ имеет статус `204`

### Requirement: REST копирования
REST SHALL принимать `POST /api/v1/specifications/{sourceAssemblyId}/copy` с явными `number` и `name` новой сборки и SHALL возвращать созданную сборку со статусом `201`.

#### Scenario: Копирование
- **WHEN** источник доступен текущей организации и тело содержит валидные `number` и `name`
- **THEN** новая сборка создаётся, строки копируются, а ответ имеет статус `201`

### Requirement: REST ошибки спецификации
REST SHALL возвращать `400` с кодом `bad_request` для нарушений валидации, `404` с кодом `not_found` для отсутствующей или чужой сборки/строки и `409` с кодом `duplicate` при повторном элементе в спецификации.

#### Scenario: Самоссылка
- **WHEN** POST добавляет строку на ту же сборку
- **THEN** ответ имеет статус `400` и код `bad_request`

#### Scenario: Строка не найдена
- **WHEN** PUT или DELETE адресует отсутствующую строку
- **THEN** ответ имеет статус `404` и код `not_found`

#### Scenario: Дублирование
- **WHEN** POST добавляет уже присутствующий элемент
- **THEN** ответ имеет статус `409` и код `duplicate`

### Requirement: REST tenant-контекст
REST SHALL получать организацию только через серверно разрешённый `OrganizationContext` и SHALL очищать контекст после каждого запроса, не принимая tenant из URL, тела или заголовка.

#### Scenario: Чужая организация
- **WHEN** клиент запрашивает `assemblyId` другой организации
- **THEN** ответ имеет статус `404`, а строки другой организации не раскрываются

### Requirement: REST плоской структуры
REST SHALL предоставлять `GET /api/v1/specifications/{assemblyId}/flat` со статусом `200` и JSON-массивом листовых элементов с полями `number`, `name` и `quantity`.

#### Scenario: Успешное получение
- **WHEN** клиент запрашивает плоскую структуру существующей сборки текущей организации без цикла
- **THEN** ответ имеет статус `200`, содержит массив листьев и возвращает их количества

### Requirement: REST ошибка цикла
REST SHALL возвращать статус `409` с кодом `bom_cycle`, если плоское разворачивание обнаруживает цикл вложенных сборок.

#### Scenario: Цикл в запросе
- **WHEN** GET `/api/v1/specifications/{assemblyId}/flat` обрабатывает состав с циклом
- **THEN** ответ имеет статус `409`, содержит код `bom_cycle` и не содержит частичный результат

### Requirement: REST ошибки доступа к спецификации
REST SHALL возвращать статус `404` с кодом `not_found`, если указанная сборка отсутствует, удалена или принадлежит другой организации.

#### Scenario: Чужая сборка
- **WHEN** клиент запрашивает flat endpoint для сборки другой организации
- **THEN** ответ имеет статус `404` с кодом `not_found`

### Requirement: REST список замен
REST SHALL предоставлять `listSubstitutes(assemblyId, item)` через `GET /api/v1/specifications/{assemblyId}/substitutes` с ссылкой основной позиции в query-параметрах `itemType` и `itemId` и SHALL возвращать статус `200` и массив `CatalogItemReference`.

#### Scenario: Список замен
- **WHEN** клиент запрашивает замены существующей строки с корректными `itemType` и `itemId`
- **THEN** ответ имеет статус `200` и содержит массив ссылок заменителей

### Requirement: REST добавление замены
REST SHALL предоставлять `addSubstitute(assemblyId, item, substituteRef)` через `POST /api/v1/specifications/{assemblyId}/substitutes` и SHALL возвращать статус `201` с добавленной ссылкой.

#### Scenario: Добавление допустимой замены
- **WHEN** тело содержит основную ссылку `item` и однотипную ссылку `substituteRef`, отсутствующую в списке
- **THEN** ответ имеет статус `201` и содержит сохранённую ссылку заменителя

### Requirement: REST удаление замены
REST SHALL предоставлять `removeSubstitute(assemblyId, item, substituteRef)` через `DELETE /api/v1/specifications/{assemblyId}/substitutes` и SHALL возвращать статус `204` после удаления.

#### Scenario: Удаление замены
- **WHEN** тело содержит основную ссылку и существующую ссылку заменителя
- **THEN** ответ имеет статус `204`, а повторный GET списка не содержит удалённую ссылку

### Requirement: REST ошибки заменителей
REST SHALL возвращать `404` с кодом `not_found` для отсутствующей или чужой строки, `409` с кодом `duplicate` для дубликата и `400` с кодом `bad_request` для кросс-типа или самозамены.

#### Scenario: Отсутствующая строка
- **WHEN** запрос списка, добавления или удаления адресует несуществующую строку
- **THEN** ответ имеет статус `404` и код `not_found`

#### Scenario: Дубликат
- **WHEN** POST повторно добавляет уже сохранённого заменителя
- **THEN** ответ имеет статус `409` и код `duplicate`

#### Scenario: Невалидная замена
- **WHEN** POST передаёт заменитель другого типа или совпадающий с основной позицией
- **THEN** ответ имеет статус `400` и код `bad_request`

### Requirement: REST признак замен
Ответ `GET /api/v1/specifications/{assemblyId}/rows` SHALL включать boolean `hasSubstitutes` для каждой строки без изменения существующих полей `item` и `quantity`.

#### Scenario: Строка отмечена
- **WHEN** строка имеет сохранённую замену
- **THEN** JSON содержит `hasSubstitutes: true`

#### Scenario: Строка не отмечена
- **WHEN** строка не имеет замен
- **THEN** JSON содержит `hasSubstitutes: false`

### Requirement: REST tenant-контекст замен
REST SHALL определять организацию через серверный `OrganizationContext` и SHALL НЕ принимать tenant из URL, тела или заголовка для операций замен.

#### Scenario: Чужая строка
- **WHEN** клиент обращается к строке другой организации
- **THEN** ответ имеет статус `404` с кодом `not_found`, а ссылки заменителей не раскрываются
