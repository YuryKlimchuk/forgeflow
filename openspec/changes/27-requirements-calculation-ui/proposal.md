# Proposal

## Why

Backend расчёта потребностей производства уже реализован (change 26): есть сохраняемый расчёт, история, источники позиций и REST-контракт `POST/GET /api/v1/plans/{planId}/calculations`. Пользователь пока не может ни запустить расчёт, ни посмотреть его результат и историю в интерфейсе. Нужен фронтенд-интерфейс, который встраивается в существующую страницу плана и позволяет запускать расчёт, видеть его позиции и историю без изменения backend.

## What Changes

- В `frontend/src/api.ts` добавляются типы `RequirementCalculationView`/`RequirementItemView` по контракту backend (id/planId вида `{value}`, `executedAt` ISO, `items`; позиция: `type` из пяти значений, `id`, `number`, `name`, `quantity`, `needType` из двух значений, `unit`, `sources` = массив `{value}`).
- В `planningApi` добавляются методы `calculate(planId)` (POST), `listCalculations(planId)` (GET список) и `getCalculation(planId, calculationId)` (GET один расчёт).
- Добавляется нормализация ошибок расчёта `humanizeRequirementError`: `not_found`, `bom_cycle`, `quantity_overflow`, `specification_item_not_found` (с идентификатором проблемной ссылки из тела ошибки backend).
- На странице `PlanDetail` добавляется секция «Расчёты потребностей» с кнопкой запуска, историей расчётов и раскрытием выбранного расчёта в таблицу позиций; без новых маршрутов в `App.tsx`.
- Позиции отображаются в порядке из API; тип, вид потребности и единица — русскими подписями; источники позиций резолвятся в номер/название головной сборки плана по UUID, неразрешимый UUID — плейсхолдер «Сборка не найдена».
- Пустой план запускается без ошибки: интерфейс показывает «Позиции отсутствуют» и не рендерит пустую таблицу.
- Ошибки запуска (`404 not_found`, `404 specification_item_not_found`, `409 bom_cycle`, `400 quantity_overflow`) показываются баннером без частичного/ложного результата и без изменения истории; кнопка блокируется на время запроса.
- Существующий UI «Плоская структура» и существующие страницы планов не меняются.

## Capabilities

### New Capabilities

- `frontend-planning-requirements`: веб-интерфейс запуска и просмотра расчётов потребностей производства на странице плана — типизированный клиент, человекочитаемые ошибки, секция с кнопкой запуска, история, таблица позиций, русские подписи, разрешение источников и обработка ошибок.

### Modified Capabilities

Нет: существующие capabilities `planning`, `planning-requirements`, `planning-requirements-rest` и `frontend-*` не меняются; контракт backend и существующий UI планов/«Плоской структуры» сохраняются без изменений. Отдельного spec про фронтенд планов ранее не существовало.

## Impact

Затрагивается только фронтенд: `frontend/src/api.ts` (типы, методы `planningApi`, `humanizeRequirementError`, расширение `ApiErrorBody`/`ApiClientError`), `frontend/src/PlanDetail.tsx` (встраивание секции) и новый компонент секции расчётов. Изменяются/добавляются тесты `frontend/src/api.test.ts`, `frontend/src/PlanDetail.test.tsx` и новый тест секции. Backend, `App.tsx` (роутинг), миграции БД и основные OpenSpec-спеки не меняются.

## Non-goals

- Изменение backend-контракта, расчётной логики или REST-эндпоинтов.
- Новые маршруты в `App.tsx`; история и просмотр остаются внутри `PlanDetail`.
- Изменение существующего UI «Плоская структура», списка планов и страницы плана.
- Экспорт результатов, документы, учёт остатков/net-потребностей.
