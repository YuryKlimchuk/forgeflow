# Spec Delta

## Purpose

Управляет прямыми строками электронных спецификаций сборочных единиц в текущей организации без хранения отдельного ресурса пустой спецификации.

## ADDED Requirements

### Requirement: Адресация спецификации
Система SHALL адресовать спецификацию по `AssemblyId` и SHALL предоставлять её для каждой сборки текущей организации без отдельной операции создания спецификации.

#### Scenario: Пустая спецификация
- **WHEN** для сборки текущей организации ещё нет строк
- **THEN** чтение по её `AssemblyId` возвращает пустой список без ошибки создания ресурса

#### Scenario: Чужая сборка
- **WHEN** запрошены строки сборки другой организации
- **THEN** система не возвращает её строки и сообщает, что сборка не найдена

### Requirement: Строка состава
Система SHALL хранить в строке ссылку на один элемент каталога через дискриминированный тип и типизированный идентификатор, а также положительное целое количество штук.

#### Scenario: Допустимое количество
- **WHEN** строка добавляется с количеством `1` или любым большим значением, представимым `int`
- **THEN** строка сохраняется с переданным количеством

#### Scenario: Недопустимое количество
- **WHEN** строка добавляется или количество изменяется на `0`, отрицательное значение или значение вне диапазона `int`
- **THEN** операция отклоняется и данные спецификации не изменяются

### Requirement: Уникальность элементов
Система SHALL разрешать не более одной строки для одного элемента каталога в одной спецификации.

#### Scenario: Повторное добавление
- **WHEN** в спецификации уже есть строка для переданного элемента каталога
- **THEN** добавление отклоняется, а существующее количество не изменяется

#### Scenario: Один элемент в разных спецификациях
- **WHEN** один элемент добавляется в спецификации двух разных сборок
- **THEN** обе операции завершаются успешно

### Requirement: Прямые ссылки состава
Система SHALL хранить только строки, непосредственно входящие в указанную сборку, и SHALL принимать ссылки на элементы каталога без проверки их существования, активности или принадлежности tenant.

#### Scenario: Ссылка на каталог
- **WHEN** добавляется ссылка с допустимым типом и идентификатором
- **THEN** строка сохраняется без вызова проверки состояния элемента каталога

#### Scenario: Неявная вложенность
- **WHEN** строка ссылается на другую сборку
- **THEN** чтение спецификации возвращает эту ссылку как одну прямую строку и не разворачивает дочернюю спецификацию

### Requirement: Запрет прямой самоссылки
Система SHALL отклонять добавление строки, если ссылка на элемент имеет тип `Assembly` и идентификатор равен `AssemblyId` спецификации.

#### Scenario: Самоссылка
- **WHEN** для сборки `A` добавляется строка, ссылающаяся на сборку `A`
- **THEN** операция отклоняется и строка не появляется в спецификации

#### Scenario: Косвенный цикл
- **WHEN** строка сборки `A` ссылается на `B`, а `B` уже ссылается на `A`
- **THEN** операция добавления не выполняет проверку цепочки и сохраняет прямую ссылку

### Requirement: Операции строк спецификации
Application-контракт SHALL предоставлять операции `addRow`, `removeRow`, `changeQuantity`, `get` и SHALL выполнять их в контексте текущей организации.

#### Scenario: Изменение строки
- **WHEN** текущая организация вызывает `changeQuantity` для существующей строки своей сборки
- **THEN** система сохраняет новое положительное количество

#### Scenario: Удаление строки
- **WHEN** текущая организация вызывает `removeRow` для существующей строки своей сборки
- **THEN** строка больше не возвращается чтением спецификации

#### Scenario: Отсутствующая строка
- **WHEN** вызывается изменение или удаление строки, которой нет в спецификации текущей организации
- **THEN** операция отклоняется ошибкой «не найдено»

### Requirement: Копирование спецификации
Операция `copy(sourceAssemblyId, number, name)` SHALL создать новую сборку с явно переданными номером и именем и SHALL скопировать в её спецификацию все исходные строки без изменения ссылок и количеств.

#### Scenario: Успешное копирование
- **WHEN** исходная сборка принадлежит текущей организации, а номер и имя новой сборки валидны
- **THEN** система возвращает новую сборку, а чтение её спецификации возвращает строки исходной спецификации 1:1

#### Scenario: Копирование пустой спецификации
- **WHEN** исходная сборка не содержит строк
- **THEN** система создаёт новую сборку с пустой спецификацией

#### Scenario: Несуществующий источник
- **WHEN** `sourceAssemblyId` отсутствует, удалён или принадлежит другой организации
- **THEN** новая сборка не создаётся

### Requirement: Tenant-изоляция
Все операции спецификации SHALL использовать идентификатор организации из серверного контекста текущего запроса и SHALL скрывать данные других организаций.

#### Scenario: Одинаковый идентификатор элемента
- **WHEN** две организации выполняют операции над спецификациями
- **THEN** строки одной организации недоступны другой организации

### Requirement: In-memory сохранность
В рамках текущего процесса система SHALL сохранять строки спецификаций в in-memory хранилище с изоляцией по организации и `AssemblyId`.

#### Scenario: Повторное чтение
- **WHEN** строка добавлена и затем выполняется чтение в том же процессе
- **THEN** чтение возвращает добавленную строку до её удаления
