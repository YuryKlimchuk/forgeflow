# Proposal

## Why

ForgeFlow хранит данные только в памяти процесса, поэтому данные теряются после перезапуска приложения, а приложение не имеет проверяемого постоянного хранилища для четырёх активных бизнес-модулей. Сейчас необходимо заложить единый PostgreSQL-путь хранения с версионируемой схемой, сохранив чистоту доменной модели и изоляцию организаций.

## What Changes

- Добавить PostgreSQL как постоянное хранилище, Spring Data JPA для адаптеров репозиториев и Flyway для версионирования схемы.
- Перевести модули `organizations`, `catalog`, `specifications` и `planning` с in-memory-репозиториев на JPA-репозитории в порядке зависимостей: `organizations` → `catalog` → `specifications` → `planning`.
- Сохранить доменные агрегаты и идентификаторы UUID независимыми от JPA; JPA-модели разместить в `infrastructure`, а преобразование выполнять мапперами.
- Обеспечить хранение и фильтрацию данных организаций в общей схеме по колонке `organization_id`; не использовать schema-per-tenant.
- Добавить транзакционные границы на application-сервисы и сохранить существующий tenant-контекст, формируемый из аутентифицированного пользователя.
- Удалить in-memory-реализации репозиториев из `src/main` и заменить их тестовыми дублями в `src/test` для unit-тестов.
- Добавить интеграционные тесты persistence-адаптеров на настоящем PostgreSQL через Testcontainers.
- Добавить `docker-compose.yml` только с PostgreSQL и Keycloak; приложение по-прежнему запускается из IDE.
- Перенести демонстрационные данные в идемпотентный SQL-файл `seed.sql`, загружаемый пользователем вручную после создания схемы Flyway; удалить Java-сидер и JSON-файлы seed-данных.
- Сохранить runtime-настройку stub-аутентификации `StubAuthenticatedUserProvider` и `MutableSubjectProvider`; `DemoDataBootstrap` больше не создаёт организацию и членство в коде.

## Capabilities

### New Capabilities

- `persistence-foundation`: постоянное хранение данных активных модулей в PostgreSQL с версионируемой схемой Flyway, tenant-изоляцией и проверяемыми persistence-адаптерами.

### Modified Capabilities

- `organizations`: операции организации и членства SHALL сохранять и читать данные через постоянное хранилище с учётом организации.
- `catalog-domain-model`: операции пяти саб-доменов каталога SHALL сохранять и читать данные через постоянное хранилище с учётом организации.
- `specifications`: спецификации и замены SHALL сохраняться и читаться через постоянное хранилище с учётом организации.
- `planning`: планы SHALL сохраняться и читаться через постоянное хранилище с учётом организации.

## Impact

Изменения затронут `pom.xml`, конфигурацию приложения, Flyway-миграции, `docker-compose.yml`, инфраструктурные пакеты четырёх модулей, композицию бинов в `WebConfig`, application-сервисы, тестовые репозитории и интеграционные тесты. Будут удалены production-классы `InMemory*Repository`, Java-сидер и JSON seed-файлы; публичные доменные и REST-контракты сохраняются, если их изменение не требуется для перехода на persistence.

## Non-goals

- Изменение бизнес-правил агрегатов, публичных API и поведения расчёта потребностей, не связанное с сохранением данных.
- Изменение пустых модулей `adminpanel`, `technology` и `directories`.
- Переход к schema-per-tenant, микросервисам или запуску ForgeFlow-приложения внутри Docker Compose.
- Интеграция приложения с Keycloak в рамках этого change.
- Автоматическая загрузка `seed.sql` приложением или Flyway.
