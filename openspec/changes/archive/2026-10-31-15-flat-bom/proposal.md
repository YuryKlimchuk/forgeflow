# Proposal

## Why

Пользователь видит только прямые строки спецификации и не может получить итоговый перечень элементов, необходимых для изделия с учётом вложенных сборок. Операция плоской структуры даст единый проверяемый результат для анализа состава непосредственно на странице спецификации.

## What Changes

- В модуле `specifications` появится операция рекурсивного разворачивания вложенных сборок в список листовых элементов.
- Количества листовых элементов будут вычисляться умножением по цепочке и суммированием одинаковых элементов из разных ветвей; результат будет сортироваться по `number`.
- Циклические ссылки сборок будут обнаруживаться и возвращать клиентскую ошибку вместо зацикливания или пропуска узла.
- REST получит endpoint `GET /api/v1/specifications/{assemblyId}/flat`.
- На детальной странице спецификации появятся кнопка «Плоская структура», состояния загрузки/ошибки и таблица результата.
- Существующие операции прямых строк и копирования спецификаций не изменяются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `specifications`: добавить поведение получения плоского состава с вычислением количеств и обнаружением циклов.
- `specifications-rest`: добавить HTTP-контракт плоского состава и ошибку цикла.
- `frontend-catalog`: добавить запуск и отображение плоского состава на детальной странице спецификации.

## Impact

Изменения затронут публичный API модуля `specifications`, его application/domain-логику и интеграцию с публичными `catalog.api` сервисами всех пяти типов элементов, REST-контроллер и обработчик ошибок, а также `frontend/src/api.ts` и `SpecificationDetail.tsx`. Потребуются unit-, REST- и Vitest-тесты. Новые зависимости и изменения схемы данных не требуются.

## Non-goals

- Изменение или сохранение рассчитанного плоского состава как отдельного ресурса.
- Изменение прямых строк спецификации.
- Вывод сборок в плоском списке.
- Расчёт потребностей производства, альтернативных элементов или складских остатков.
