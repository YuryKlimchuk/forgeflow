# Spec Delta

## ADDED Requirements

### Requirement: Открытие детальной страницы каталога
Приложение SHALL открывать детальную страницу записи выбранного типа по клику на строку списка без изменения URL и SHALL предоставлять действие «Назад».

#### Scenario: Открытие детали Part
- **WHEN** пользователь нажимает строку записи Part в таблице
- **THEN** таблица заменяется детальной страницей этой записи с `number`, `name`, `createdAt` и `updatedAt`

#### Scenario: Возврат к списку
- **WHEN** пользователь нажимает «Назад» на детальной странице
- **THEN** приложение показывает список ранее выбранного типа без изменения URL

### Requirement: Получение данных детальной страницы
Frontend SHALL получать представление выбранной записи через `GET /api/v1/{type}/{id}` и SHALL показывать данные этой записи после успешного ответа.

#### Scenario: Успешная загрузка детали
- **WHEN** открытая детальная страница отправляет GET для записи, а API возвращает 200 с `number`, `name`, `createdAt` и `updatedAt`
- **THEN** страница отображает все четыре значения

#### Scenario: Деталь не найдена
- **WHEN** запрос детальной страницы получает 404 с кодом `not_found`
- **THEN** интерфейс показывает сообщение «Запись не найдена»

### Requirement: Создание записи на экране списка
Приложение SHALL оставлять форму создания новой записи на экране списка и SHALL НЕ показывать её как обязательную часть детальной страницы.

#### Scenario: Создание из списка
- **WHEN** пользователь находится на списке выбранного типа, заполняет номер и название и отправляет форму
- **THEN** приложение отправляет POST для текущего типа и обновляет список

### Requirement: Открытие спецификации сборки
Детальная страница Assembly SHALL предоставлять действие «Состав», открывающее детальную страницу спецификации этой сборки без ручного ввода её идентификатора.

#### Scenario: Переход к составу
- **WHEN** пользователь нажимает «Состав» на детальной странице Assembly
- **THEN** приложение показывает страницу спецификации и запрашивает `GET /api/v1/specifications/{assemblyId}/rows`

### Requirement: Ошибки и состояния операций детальных страниц
Приложение SHALL отображать человекочитаемые ошибки 400, 404 и 409 и SHALL показывать состояние загрузки для получения детали и спецификации.

#### Scenario: Ошибка конфликта
- **WHEN** переименование, удаление или операция спецификации получает 409
- **THEN** интерфейс показывает сообщение, соответствующее коду ошибки

#### Scenario: Загрузка детали
- **WHEN** GET детальной страницы выполняется
- **THEN** интерфейс показывает индикатор загрузки до получения ответа

#### Scenario: Загрузка спецификации
- **WHEN** GET строк спецификации выполняется
- **THEN** интерфейс показывает индикатор загрузки и не показывает результат как завершённый до ответа

## MODIFIED Requirements

### Requirement: Переименование детали
Пользователь SHALL иметь возможность переименовать запись выбранного типа только на детальной странице записи, отправляя `PUT /api/v1/{type}/{id}/name`.

#### Scenario: Успешное переименование
- **WHEN** пользователь подтверждает новое непустое название, а API возвращает 204
- **THEN** приложение отображает новое название у соответствующей детали

#### Scenario: Переименование на детальной странице
- **WHEN** пользователь открывает деталь, выбирает «Переименовать», вводит непустое новое название и подтверждает его, а API возвращает 204
- **THEN** детальная страница отображает новое название

#### Scenario: Переименование Vzk
- **WHEN** пользователь переименовывает запись на детальной странице вкладки «ВЗК»
- **THEN** приложение отправляет PUT на `/api/v1/vzks/{id}/name`

### Requirement: Подтверждение удаления детали
Приложение SHALL предоставлять удаление записи только на её детальной странице, SHALL запрашивать подтверждение и SHALL отправлять DELETE только после подтверждения.

#### Scenario: Удаление после подтверждения
- **WHEN** пользователь на детальной странице подтверждает удаление, а API возвращает 204
- **THEN** приложение возвращается к списку текущего типа без удалённой записи

#### Scenario: Отмена удаления
- **WHEN** пользователь отменяет подтверждение удаления на детальной странице
- **THEN** приложение не отправляет запрос DELETE и остаётся на детальной странице

#### Scenario: Отмена удаления Buy
- **WHEN** пользователь отменяет подтверждение на вкладке «Покупные»
- **THEN** запрос DELETE не отправляется

### Requirement: Управление строками спецификации
Интерфейс SHALL предоставлять на детальной странице спецификации выбранной сборки просмотр, добавление, изменение количества и удаление прямых строк спецификации.

#### Scenario: Открытие спецификации
- **WHEN** пользователь открывает «Состав» сборки
- **THEN** интерфейс отображает строки с элементом и количеством после успешного GET

#### Scenario: Добавление строки
- **WHEN** пользователь выбирает тип, идентификатор элемента и положительное количество и подтверждает добавление
- **THEN** интерфейс отправляет POST на `/api/v1/specifications/{assemblyId}/rows` и обновляет строки после ответа 201

#### Scenario: Изменение количества
- **WHEN** пользователь вводит новое положительное количество существующей строки
- **THEN** интерфейс отправляет PUT на `/api/v1/specifications/{assemblyId}/rows` и отображает новое количество после ответа 204

#### Scenario: Удаление строки
- **WHEN** пользователь подтверждает удаление строки спецификации
- **THEN** интерфейс отправляет DELETE на `/api/v1/specifications/{assemblyId}/rows` и исключает строку после ответа 204

### Requirement: Копирование спецификации в UI
Детальная страница спецификации SHALL предоставлять операцию «Скопировать» с вводом номера и имени новой сборки.

#### Scenario: Успешное копирование
- **WHEN** пользователь вводит валидные номер и имя и нажимает «Скопировать»
- **THEN** интерфейс отправляет `POST /api/v1/specifications/{sourceAssemblyId}/copy` и показывает созданную сборку или её идентификатор
