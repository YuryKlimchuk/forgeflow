# Design

## Context

См. `proposal.md` — Why. Текущие пять сущностей `catalog` содержат только типизированный ID, а Maven-проект не содержит `commons-lang3`. Домен должен оставаться свободным от Spring/JPA/персистентности; корневой модуль сохраняет зависимость только от `directories`.

## Goals / Non-Goals

**Goals:**

- Представить общий жизненный цикл и обязательные атрибуты всех пяти типов каталога единообразно.
- Обеспечить fail-fast валидацию только `number` и `name`.
- Выразить сохранение и логическое удаление через driven ports без выбора хранилища.
- Сохранить возможность последующей JPA-реализации без загрязнения домена.

**Non-Goals:**

- Формат номера, уникальность, максимальная длина и прочие бизнес-правила.
- Чтение через `findById`: пользовательский scope ограничен `save` и `delete`.
- JPA-маппинг, миграции, инфраструктурные адаптеры и production in-memory хранилище.
- Связь `organizationId` с `organizations`, `shared` или типом `OrganizationId`.

## Decisions

### D1. Единый набор полей

Каждая сущность получает `number: String`, `name: String`, `organizationId: UUID`, `createdAt: Instant`, `updatedAt: Instant` и nullable `deletedAt: Instant`, помимо существующего ID. `Instant` выбран как абсолютная временная шкала, не зависящая от часового пояса процесса и пригодная для аудита и последующего PostgreSQL-маппинга.

Альтернатива `LocalDateTime` отклонена: она не выражает однозначный момент времени при разных часовых поясах. `createdBy`/`updatedBy` не добавляются, поскольку не входят в требование.

### D2. Создание и валидация

Публичная фабрика/конструктор каждой сущности SHALL проверять `number` и `name` через `StringUtils.isBlank` и выбрасывать `IllegalArgumentException` с сообщением, называющим поле и причину. ID, `organizationId` и временные значения SHALL проверяться через `Objects.requireNonNull` с понятными сообщениями. Поля не будут нормализоваться или обрезаться: пробельное значение отклоняется, но допустимые непустые значения сохраняются как переданы.

Для реализации базовой проверки добавить `org.apache.commons:commons-lang3` в Maven. Стандартный `String.isBlank()` не выбран, так как проектная конвенция явно требует `StringUtils`.

### D3. Soft delete в сущности

`deletedAt == null` означает активную сущность. `markDeleted()` SHALL установить `deletedAt` в текущий `Instant` и обновить `updatedAt`; повторный вызов SHALL быть идемпотентным и не восстанавливать сущность. Восстановление и отдельный статус не вводятся.

Альтернатива — оставить soft delete только семантикой репозитория — отклонена: тогда доменный объект не содержит проверяемого состояния удаления, а адаптер мог бы физически удалить запись. `deletedAt` выбран вместо boolean, поскольку сохраняет момент удаления.

### D4. Repository ports

Для каждого типа создать отдельный интерфейс driven port в доменном подпакете соответствующей сущности. Интерфейс содержит только `save(<Entity> entity)` и `delete(<Id> id)`, с типами конкретной сущности и её ID. `delete` означает вызов `markDeleted()` и сохранение изменённой сущности в будущей реализации; физическое удаление SHALL быть запрещено контрактом.

`findById` не добавляется: без требования чтения он расширил бы API и потребовал определить поведение для удалённых записей. Возврат `void` для `save`/`delete` выбран, так как требование задаёт операции, но не результат. Реализующий адаптер может иметь внутреннюю техническую сигнатуру, не меняющую доменный порт.

### D5. Отсутствие адаптеров

В production-коде не создаются JPA-адаптеры, аннотации, миграции или in-memory реализация. Проверка soft delete выполняется unit-тестами сущностей и контрактными тестами порта через test-scope fake только при необходимости; fake не является частью production API.

### D6. Границы модулей

`organizationId` остаётся `UUID`, а ID остаются в `com.forgeflow.catalog.api`. Новые repository ports используют только типы `catalog` и не добавляют зависимости на `organizations` или `shared`; архитектурная проверка Spring Modulith должна сохранить текущий граф.

## Risks / Trade-offs

- **[Риск]** Требование добавить `commons-lang3` увеличивает dependency graph. → **Митигировать:** добавить только основную библиотеку и проверить Maven dependency tree; не добавлять дополнительные validation starters.
- **[Риск]** `delete(id)` без результата не сообщает вызывающему, существовала ли сущность. → **Митигировать:** оставить это неопределённым до появления use case-требования; не вводить чтение или исключения преждевременно.
- **[Риск]** `deletedAt` в каждой из пяти сущностей дублирует структуру. → **Митигировать:** сохранить явные типизированные сущности и одинаковые контракты; общий базовый класс не вводить, чтобы не навязать наследование доменной модели.
- **[Риск]** Значения `createdAt` и `updatedAt` могут прийти некорректно из вызывающего кода. → **Митигировать:** проверять non-null; правила порядка и часовых зон не добавлять без отдельного решения.

## Migration Plan

Миграции БД не выполняются, поскольку персистентность не входит в change. Реализация добавляется как совместимое изменение исходного доменного контракта только в рамках согласованной BREAKING-дельты; откат удаляет новые поля, методы и порты, возвращая код к состоянию change `1`.

## Open Questions

- Правила уникальности `number` в пределах организации и их область действия остаются для отдельного change.
- Формат и максимальная длина `number`/`name` остаются для отдельного change.
- Поведение будущего чтения удалённых сущностей и требования к `findById` остаются для отдельного change.
