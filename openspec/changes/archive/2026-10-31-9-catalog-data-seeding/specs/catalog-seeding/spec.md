# Spec Delta

## Purpose

Предоставляет разработчикам автоматическое и безопасное наполнение in-memory каталога тестовыми данными из локального JSON-файла при запуске ForgeFlow без зависимости от продакшн-миграций.

## ADDED Requirements

### Requirement: Управляемая загрузка каталога
Загрузчик каталога SHALL запускаться автоматически при старте приложения и SHALL загружать данные только при `forgeflow.seed.enabled=true`.

#### Scenario: Загрузка включена
- **WHEN** приложение стартует с `forgeflow.seed.enabled=true` и доступным файлом данных
- **THEN** загрузчик читает файл и сохраняет все записи в каталог

#### Scenario: Загрузка выключена
- **WHEN** приложение стартует с `forgeflow.seed.enabled=false`
- **THEN** загрузчик не читает файл и не сохраняет записи

### Requirement: Конфигурация источника данных
Свойство `forgeflow.seed.data-file` SHALL задавать путь к JSON-файлу источника, а значением по умолчанию SHALL быть `seed-data/catalog.json` относительно рабочей директории.

#### Scenario: Пользовательский путь
- **WHEN** приложение запускается с заданным `forgeflow.seed.data-file`
- **THEN** загрузчик использует указанный путь вместо пути по умолчанию

### Requirement: Пропуск отсутствующего файла
При включённой загрузке и отсутствии JSON-файла загрузчик SHALL записать информационное сообщение и SHALL завершить запуск без исключения и без создания записей.

#### Scenario: Файл не найден
- **WHEN** `forgeflow.seed.enabled=true`, но файл `forgeflow.seed.data-file` отсутствует
- **THEN** приложение продолжает запуск, загрузчик не создаёт записи и пишет info-лог о пропуске

### Requirement: Формат входных записей
Загрузчик SHALL принимать JSON-массив объектов с обязательными полями `number`, `name` и `type`, где `type` имеет значение `ASSEMBLY` или `PART`.

#### Scenario: Запись сборочной единицы
- **WHEN** массив содержит `{"number":"A-1","name":"Корпус","type":"ASSEMBLY"}`
- **THEN** загрузчик создаёт и сохраняет одну `Assembly` с номером `A-1` и именем `Корпус`

#### Scenario: Запись детали
- **WHEN** массив содержит `{"number":"P-1","name":"Винт","type":"PART"}`
- **THEN** загрузчик создаёт и сохраняет одну `Part` с номером `P-1` и именем `Винт`

### Requirement: Принадлежность демо-организации
Каждая запись, созданная загрузчиком, SHALL принадлежать организации, созданной `DemoDataBootstrap` при текущем запуске приложения.

#### Scenario: Связь с организацией запуска
- **WHEN** загрузчик обрабатывает доступный файл после создания демо-организации
- **THEN** сохранённые `Assembly` и `Part` содержат тот же `OrganizationId`, что и демо-организация

### Requirement: Системные атрибуты загружаемых сущностей
Загрузчик SHALL создавать идентификаторы через `AssemblyId.generate()` или `PartId.generate()` и SHALL задавать временные метки создания и обновления текущим `Instant`.

#### Scenario: Генерация системных атрибутов
- **WHEN** загрузчик сохраняет запись любого поддерживаемого типа
- **THEN** сущность получает непустой типизированный идентификатор, а `createdAt` и `updatedAt` равны времени загрузки

### Requirement: Сохранение всех записей
Загрузчик SHALL сохранять каждую запись входного JSON без дедупликации по `number`.

#### Scenario: Повторяющиеся номера во входе
- **WHEN** входной массив содержит две записи с одинаковым `number`
- **THEN** загрузчик обрабатывает и сохраняет обе записи

### Requirement: In-memory хранение сборочных единиц
Реализация порта `AssemblyRepository` SHALL сохранять и логически удалять `Assembly` в памяти процесса.

#### Scenario: Сохранение сборочной единицы
- **WHEN** вызывается `save` с `Assembly`
- **THEN** последующая операция чтения, предоставленная реализацией репозитория для проверки, находит сохранённую сущность

#### Scenario: Логическое удаление сборочной единицы
- **WHEN** вызывается `delete` с идентификатором сохранённой `Assembly`
- **THEN** сущность помечается удалённой через `markDeleted()` и не удаляется физически из внутреннего хранилища

### Requirement: Подготовка JSON из Excel
Скрипт извлечения SHALL читать локальный Excel-файл, преобразовывать `Обозначение` в `number`, `Наименование` в `name`, тип `СЕ` в `ASSEMBLY` и тип `Д` в `PART`, а также исключать повторяющиеся `number` в результирующем JSON.

#### Scenario: Генерация seed-файла
- **WHEN** скрипт запускается с Excel-источником и путём JSON-назначения
- **THEN** JSON содержит массив объектов требуемого формата без повторяющихся значений `number`
