# Design

## Context

Сейчас каталог содержит доменные порты для `Assembly` и `Part`, но in-memory адаптер есть только для `Part`. Composition root собирается в `WebConfig`, а демо-организация создаётся отдельным `CommandLineRunner` в `DemoDataBootstrap`. Изменение должно остаться инструментом разработки: локальный Excel не входит в репозиторий, JSON не становится миграцией, а доменный слой не получает зависимостей от Spring или файловой системы.

## Goals / Non-Goals

**Goals:**

- Загружать локальный JSON в `AssemblyRepository` и `PartRepository` во время старта.
- Управлять загрузкой через два конфигурационных свойства.
- Обеспечить in-memory хранение сборочных единиц для загрузчика.
- Дать воспроизводимый Python-инструмент подготовки JSON из Excel.
- Сохранить запуск приложения без локального файла.

**Non-Goals:**

- Добавление REST-эндпоинта или пользовательского UI для импорта.
- Изменение доменных сущностей, repository-портов и бизнес-правил каталога.
- Постоянное хранение, Flyway-миграции, импорт `Buy`, `Standart` или `Vzk`.
- Коммит сгенерированного JSON или исходного Excel.

## Decisions

### D1. Локальный JSON вне git

JSON является runtime-источником, а не частью приложения. Дефолтный путь — `seed-data/catalog.json`, пользовательский путь задаётся `forgeflow.seed.data-file`. Excel остаётся локальным входом Python-скрипта. Альтернатива — включить JSON в resources, но это сделало бы демо-данные частью артефакта и усложнило их замену.

### D2. Явный флаг включения

`forgeflow.seed.enabled` имеет значение `true` по умолчанию для dev-сценария; при `false` загрузчик не выполняет действий. Это предпочтительнее профиля Spring, поскольку функциональность можно отключить одной настройкой независимо от выбранного профиля.

### D3. CommandLineRunner после подготовки демо-организации

Загрузчик подключается через `CommandLineRunner`, аналогично `DemoDataBootstrap`, и получает идентификатор организации через тот же публичный контекст/сервис, который используется стартовой инициализацией. Порядок бинов или явная координация запуска должна гарантировать, что демо-организация создана до импорта. REST-эндпоинт не добавляется, потому что импорт является локальным dev-инструментом.

### D4. Файловый адаптер в composition root

Чтение JSON и преобразование входных записей располагаются в инфраструктурной/корневой части, а доменные factory остаются единственным способом создания сущностей. Загрузчик генерирует `AssemblyId`/`PartId`, передаёт `Instant.now()` и `OrganizationId`, затем вызывает существующие repository ports.

### D5. InMemoryAssemblyRepository

Добавляется отдельный in-memory адаптер для `AssemblyRepository`, подключаемый `@Bean` в `WebConfig`. Он хранит объекты по `AssemblyId`, а `delete` вызывает `markDeleted()` без физического удаления. Домен/application не изменяются. Наличие диагностической операции чтения в адаптере допускается для тестов и не расширяет доменный порт.

### D6. Дедупликация только в Python-скрипте

Скрипт читает колонки `Обозначение` и `Наименование`, преобразует типы `СЕ`/`Д` и исключает повторные номера при генерации. Runtime-загрузчик не дедуплицирует и не вводит дополнительные бизнес-правила: он сохраняет все элементы корректного JSON в порядке входного массива.

### D7. Отсутствующий файл — штатный skip

Проверка существования выполняется до чтения. Отсутствующий файл приводит к info-логу и нормальному завершению загрузчика; ошибки не должны препятствовать запуску приложения в режиме без seed-файла. Ошибки существующего, но некорректного JSON не маскируются как отсутствие файла и должны быть покрыты выбранной стратегией тестирования при реализации.

## Risks / Trade-offs

- **[Риск]** Демо-организация может быть создана повторно при каждом запуске существующего bootstrap. → **Митигация:** загрузчик использует организацию, созданную текущим bootstrap; поведение повторного запуска не расширяется сверх согласованного scope.
- **[Риск]** Некорректные значения JSON могут привести к исключению доменной factory. → **Митигация:** валидировать формат в скрипте и покрыть загрузчик тестами на валидные записи; не добавлять новые бизнес-правила.
- **[Риск]** Большой Excel может требовать памяти. → **Митигация:** использовать `openpyxl` в режиме, подходящем для локального инструмента, и писать компактный JSON; оптимизация runtime не входит в scope.
- **[Риск]** Локальный путь может случайно попасть в git. → **Митигация:** добавить шаблоны `seed-data/*.json` и исходного Excel/локальных Excel-файлов в `.gitignore`, сохранив скрипт.

## Migration Plan

Миграции базы данных не требуются. Для локального использования разработчик устанавливает `openpyxl`, запускает скрипт с Excel-файлом и получает игнорируемый `seed-data/catalog.json`; приложение затем загружает его при старте. Откат выполняется удалением новых загрузчика, адаптера, скрипта и связанных ignore/test-файлов; существующие доменные контракты и данные хранилища не затрагиваются.

## Open Questions

Нет: источник, формат, порядок запуска, поведение при отсутствии файла и границы runtime-функциональности согласованы.
