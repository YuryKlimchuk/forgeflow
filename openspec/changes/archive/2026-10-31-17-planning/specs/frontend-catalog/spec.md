# Spec Delta

## ADDED Requirements

### Requirement: Открытие раздела планов
Приложение SHALL предоставлять переход в раздел «Планы» со списком производственных планов без отображения UUID в пользовательском интерфейсе.

#### Scenario: Открытие планов
- **WHEN** пользователь выбирает раздел «Планы»
- **THEN** приложение открывает список производственных планов

### Requirement: Управление планами
Приложение SHALL предоставлять список и создание планов, а детальная страница плана SHALL отображать период и элементы с операциями добавления, изменения количества и удаления.

#### Scenario: Создание и открытие плана
- **WHEN** пользователь вводит имя, год и месяц и подтверждает создание
- **THEN** приложение отправляет запрос создания, показывает созданный план в списке и позволяет открыть его детальную страницу

#### Scenario: Изменение элемента
- **WHEN** пользователь на детальной странице изменяет положительное количество элемента
- **THEN** приложение отправляет запрос изменения и показывает новое количество после успешного ответа

#### Scenario: Удаление элемента
- **WHEN** пользователь подтверждает удаление элемента плана
- **THEN** приложение отправляет запрос удаления и исключает элемент из таблицы

### Requirement: Выбор сборки для добавления в план
Форма добавления элемента плана SHALL предоставлять выпадающий список сборок с поиском по `number` или `name` и SHALL НЕ требовать ручного ввода UUID.

#### Scenario: Поиск сборки
- **WHEN** пользователь открывает добавление элемента плана и вводит часть номера или названия сборки
- **THEN** список показывает только соответствующие сборки и отображает их номер и название

### Requirement: Отображение плоской структуры плана
Детальная страница плана SHALL предоставлять кнопку «Плоская структура» и SHALL отображать результат с колонками `number`, `name`, `quantity` без UUID.

#### Scenario: Успешный расчёт плана
- **WHEN** пользователь нажимает «Плоская структура», а API возвращает результат
- **THEN** интерфейс показывает суммированные строки в порядке номеров

#### Scenario: Выполняющийся расчёт
- **WHEN** запрос плоской структуры плана выполняется
- **THEN** кнопка блокируется и отображается состояние загрузки

## MODIFIED Requirements

### Requirement: Отображение ошибок API
Приложение SHALL отображать человекочитаемое сообщение для ошибок API со статусами 400, 404 и 409, включая операции планов.

#### Scenario: Дублирующий номер
- **WHEN** операция создания получает 409 с `error` равным `duplicate`
- **THEN** интерфейс сообщает, что деталь с таким номером уже существует

#### Scenario: Некорректные данные
- **WHEN** операция получает 400 с `error` равным `bad_request`
- **THEN** интерфейс отображает сообщение о некорректных данных запроса

#### Scenario: Деталь не найдена
- **WHEN** операция получает 404 с `error` равным `not_found`
- **THEN** интерфейс сообщает, что деталь не найдена

#### Scenario: Ошибка плана
- **WHEN** операция плана получает 409 с кодом `duplicate`
- **THEN** интерфейс сообщает о дублировании имени или элемента плана
