# Spec Delta

## Purpose

Предоставляет tenant-scoped HTTP-контракт для создания и управления производственными планами, их элементами и результатом плоской структуры.

## ADDED Requirements

### Requirement: REST планы
REST SHALL предоставлять создание планов через `POST /api/v1/plans`, получение через `GET /api/v1/plans/{id}` и список через `GET /api/v1/plans`.

#### Scenario: Создание и чтение
- **WHEN** клиент отправляет валидные имя, год и месяц
- **THEN** POST возвращает статус 201, а GET созданного плана возвращает статус 200 и его данные

### Requirement: REST элементы плана
REST SHALL предоставлять список элементов через GET плана, добавление через `POST /api/v1/plans/{id}/items`, изменение количества через PUT и удаление через DELETE того же ресурса элемента.

#### Scenario: Управление элементом
- **WHEN** клиент добавляет сборку с количеством 2, изменяет количество на 4 и удаляет элемент
- **THEN** операции возвращают 201, 204 и 204 соответственно, а последующее чтение не содержит элемент

### Requirement: REST плоской структуры плана
REST SHALL предоставлять `GET /api/v1/plans/{id}/flat` со статусом 200 и массивом объектов `number`, `name`, `quantity`, отсортированным по `number`.

#### Scenario: Получение расчёта
- **WHEN** клиент запрашивает плоскую структуру доступного плана
- **THEN** ответ содержит суммированные листовые элементы без UUID

### Requirement: REST ошибки планов
REST SHALL возвращать 400 для невалидного месяца или количества, 404 для отсутствующего или чужого плана, сборки или элемента и 409 для дублирующего имени или сборки в плане.

#### Scenario: Дублирующее имя
- **WHEN** создание получает имя уже существующего в организации плана
- **THEN** ответ имеет статус 409 и код `duplicate`

#### Scenario: Невалидное количество
- **WHEN** добавление или изменение получает количество 0
- **THEN** ответ имеет статус 400 и код `bad_request`

#### Scenario: Отсутствующий ресурс
- **WHEN** запрос адресует чужой план или отсутствующий элемент
- **THEN** ответ имеет статус 404 и код `not_found`

### Requirement: REST tenant-контекст
REST SHALL определять организацию только через серверный `OrganizationContext` и SHALL не принимать tenant из URL, тела или пользовательского заголовка.

#### Scenario: Изоляция запроса
- **WHEN** клиент организации A запрашивает идентификатор плана организации B
- **THEN** ответ имеет статус 404 и не раскрывает данные плана B
