# Spec Delta

## MODIFIED Requirements

### Requirement: Отображение списка деталей
Приложение SHALL отображать на одном экране таблицу активных записей выбранного типа каталога с колонками номера, названия и даты создания.

#### Scenario: Переключение типа
- **WHEN** пользователь выбирает вкладку «Покупные»
- **THEN** приложение загружает `/api/v1/buys` и отображает записи Buy в общей таблице

#### Scenario: Начальное состояние
- **WHEN** приложение открывает экран каталога
- **THEN** выбрана вкладка «Детали» и загружается `/api/v1/parts`

### Requirement: Создание детали
Пользователь SHALL иметь возможность создавать запись выбранного типа через общую форму, отправляя `POST` на endpoint выбранного типа.

#### Scenario: Создание Assembly
- **WHEN** выбрана вкладка «Сборки», пользователь отправляет валидные номер и название
- **THEN** приложение отправляет `POST /api/v1/assemblies` и добавляет созданную запись в таблицу

### Requirement: Переименование детали
Пользователь SHALL иметь возможность переименовать запись выбранного типа через общий интерфейс, отправляя `PUT /api/v1/{type}/{id}/name`.

#### Scenario: Переименование Vzk
- **WHEN** выбрана вкладка «ВЗК» и пользователь подтверждает новое имя
- **THEN** приложение отправляет PUT на `/api/v1/vzks/{id}/name` и отображает новое имя

### Requirement: Подтверждение удаления детали
Приложение SHALL запрашивать подтверждение перед удалением записи выбранного типа и SHALL отправлять DELETE только после подтверждения.

#### Scenario: Отмена удаления Buy
- **WHEN** пользователь отменяет подтверждение на вкладке «Покупные»
- **THEN** запрос DELETE не отправляется

### Requirement: Вкладки типов каталога
Приложение SHALL отображать вкладки «Детали», «Сборки», «Покупные», «Стандартные» и «ВЗК», каждая из которых SHALL выбирать соответствующий endpoint и набор данных.

#### Scenario: Выбор всех вкладок
- **WHEN** пользователь последовательно выбирает пять вкладок
- **THEN** приложение использует endpoints `/api/v1/parts`, `/api/v1/assemblies`, `/api/v1/buys`, `/api/v1/standarts` и `/api/v1/vzks`

### Requirement: Generic-клиент каталога
Frontend SHALL использовать единый типизированный клиент для list, create, rename и delete операций любого из пяти типов каталога.

#### Scenario: CRUD через общий клиент
- **WHEN** пользователь выполняет создание, переименование и удаление на выбранной вкладке
- **THEN** клиент отправляет запросы с endpoint и данными текущего типа без отдельной логики запроса для каждого типа

### Requirement: Ошибки и загрузка каталога
Приложение SHALL отображать сообщения ошибок API со статусами 400, 404 и 409 и SHALL блокировать повторную активную операцию до получения её результата для выбранного типа.

#### Scenario: Пустой Buy
- **WHEN** вкладка «Покупные» открыта и API возвращает пустой массив
- **THEN** приложение показывает пустую таблицу без ошибки и позволяет создать запись
