# Spec Delta

## MODIFIED Requirements

### Requirement: Формат входных записей
Загрузчик SHALL принимать JSON-массив объектов с обязательными полями `number`, `name` и `type`, где `type` имеет одно из значений `ASSEMBLY`, `PART`, `BUY`, `STANDART` или `VZK`.

#### Scenario: Записи всех типов
- **WHEN** массив содержит по одной записи каждого из пяти поддерживаемых значений `type`
- **THEN** загрузчик сохраняет по одной сущности соответствующего типа с переданными номером и именем

#### Scenario: Запись сборочной единицы
- **WHEN** массив содержит `{"number":"A-1","name":"Корпус","type":"ASSEMBLY"}`
- **THEN** загрузчик создаёт и сохраняет одну `Assembly` с номером `A-1` и именем `Корпус`

#### Scenario: Запись детали
- **WHEN** массив содержит `{"number":"P-1","name":"Винт","type":"PART"}`
- **THEN** загрузчик создаёт и сохраняет одну `Part` с номером `P-1` и именем `Винт`

### Requirement: Сохранение всех записей
Загрузчик SHALL сохранять каждую запись входного JSON без дедупликации по паре `type` и `number`.

#### Scenario: Повторяющиеся номера разных типов
- **WHEN** входной массив содержит одинаковый `number` для двух разных типов
- **THEN** загрузчик сохраняет обе записи в репозитории соответствующего типа

#### Scenario: Повторяющиеся номера во входе
- **WHEN** входной массив содержит две записи с одинаковым `number`
- **THEN** загрузчик обрабатывает и сохраняет обе записи

## ADDED Requirements

### Requirement: Демо-объём каталога
Поставляемый демо-файл каталога SHALL содержать от 50 до 100 записей каждого из пяти типов `PART`, `ASSEMBLY`, `BUY`, `STANDART` и `VZK`.

#### Scenario: Проверка состава файла
- **WHEN** демо-файл `seed-data/catalog.json` загружается как JSON-массив
- **THEN** количество записей каждого поддерживаемого типа находится в диапазоне от 50 до 100 включительно

### Requirement: Паттерны номеров каталога
Демо-загрузка SHALL устанавливать для организации паттерны `Д-\d{4}`, `СБ-\d{4}`, `ПОК-\d{4}`, `СТ-\d{4}` и `ВЗК-\d{4}` для типов `PART`, `ASSEMBLY`, `BUY`, `STANDART` и `VZK` соответственно.

#### Scenario: Соответствие номеров паттернам
- **WHEN** загружены демо-записи каталога и настройки организации
- **THEN** каждый номер записи соответствующего типа удовлетворяет установленному для него паттерну

### Requirement: Детерминированная генерация seed-файлов
Скрипт `scripts/generate-seed-data.py` SHALL без внешнего источника данных генерировать одинаковые `seed-data/catalog.json`, `seed-data/specifications.json` и данные паттернов при каждом запуске.

#### Scenario: Повторная генерация
- **WHEN** скрипт запускается дважды в одинаковом окружении
- **THEN** содержимое каждого выходного файла совпадает побайтно

### Requirement: Безопасная загрузка спецификаций
Загрузчик SHALL создавать спецификацию для каждой seed-сборки после загрузки каталога и SHALL разрешать ссылки строк по паре `type` и `number` в пределах демо-организации.

#### Scenario: Ссылка на элемент каталога
- **WHEN** строка `seed-data/specifications.json` ссылается на существующие `type` и `number`
- **THEN** в спецификации сборки сохраняется строка с идентификатором найденного элемента и указанным количеством

#### Scenario: Несуществующая ссылка
- **WHEN** строка ссылается на отсутствующие `type` и `number`
- **THEN** загрузчик не создаёт для неё строку и сообщает об ошибке загрузки
