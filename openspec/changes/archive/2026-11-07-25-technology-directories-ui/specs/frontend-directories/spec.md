# Spec Delta

## Purpose

Предоставляет пользователю веб-интерфейс для ведения справочников «Материалы» и «Сортаменты» через существующий REST-контракт `/api/v1/materials` и `/api/v1/sortaments`.

## ADDED Requirements

### Requirement: Типизированные клиенты справочников
Frontend SHALL использовать типизированные API-функции для списка, создания, получения, обновления и удаления материалов и сортаментов, отправляя запросы на `/api/v1/materials` и `/api/v1/sortaments` соответственно через `authFetch` и `toJsonOrThrow`.

#### Scenario: Список материалов
- **WHEN** компонент справочников открывает вкладку «Материалы»
- **THEN** отправляется `GET /api/v1/materials` и возвращённый массив представляется типизированными объектами с `id:{value}`

#### Scenario: Создание и обновление
- **WHEN** компонент справочников создаёт материал и обновляет сортамент
- **THEN** отправляются `POST /api/v1/materials` с телом `{number,name,standardType,standard,unit}` и `PUT /api/v1/sortaments/{id}` с телом `{name,standardType,standard,unit}`

### Requirement: Список материалов
Приложение SHALL загружать список материалов через `GET /api/v1/materials` и отображать для каждой записи колонки «Номер», «Наименование», «Тип стандарта», «Обозначение стандарта» и «Единица измерения».

#### Scenario: Успешная загрузка списка
- **WHEN** вкладка «Материалы» открыта и `GET /api/v1/materials` возвращает массив материалов
- **THEN** таблица отображает `number`, `name`, `standardType`, `standard` и `unit` каждой записи

#### Scenario: Пустой список
- **WHEN** `GET /api/v1/materials` возвращает пустой массив
- **THEN** интерфейс показывает сообщение об отсутствии записей и форму создания

### Requirement: Создание материала
Приложение SHALL предоставлять форму создания материала с обязательными полями `number`, `name`, `standardType` (select ГОСТ/DIN/ISO/Другое), `standard` и `unit` и SHALL отправлять `POST /api/v1/materials` только при заполнении всех полей.

#### Scenario: Успешное создание
- **WHEN** пользователь заполняет все поля и подтверждает создание
- **THEN** отправляется `POST /api/v1/materials` с телом `{number,name,standardType,standard,unit}` и после ответа 201 список обновляется

#### Scenario: Блокировка при пустом поле
- **WHEN** любое из полей `number`, `name`, `standardType`, `standard` или `unit` пусто
- **THEN** запрос создания не отправляется

### Requirement: Детальная страница материала
Приложение SHALL открывать детальную страницу материала по клику на строку, получать её через `GET /api/v1/materials/{id}` и отображать все поля, включая `createdAt` и `updatedAt`.

#### Scenario: Открытие детали
- **WHEN** пользователь кликает по строке материала
- **THEN** отправляется `GET /api/v1/materials/{id}` и отображаются `number`, `name`, `standardType`, `standard`, `unit`, `createdAt`, `updatedAt`

### Requirement: Редактирование и удаление материала
Детальная страница материала SHALL позволять редактировать `name`, `standardType`, `standard` и `unit` через `PUT /api/v1/materials/{id}` без изменения `number` и SHALL удалять запись через `DELETE /api/v1/materials/{id}` только после подтверждения.

#### Scenario: Редактирование без номера
- **WHEN** пользователь изменяет изменяемые поля и сохраняет
- **THEN** отправляется `PUT /api/v1/materials/{id}` с телом `{name,standardType,standard,unit}` и `number` не изменяется

#### Scenario: Удаление с подтверждением
- **WHEN** пользователь подтверждает удаление материала
- **THEN** отправляется `DELETE /api/v1/materials/{id}` и интерфейс возвращается к списку

### Requirement: Сортаменты
Приложение SHALL реализовать для сортаментов список, создание, детальную страницу, редактирование изменяемых полей и удаление с теми же полями, что и материалы, используя `/api/v1/sortaments`.

#### Scenario: Список и создание сортамента
- **WHEN** открыта вкладка «Сортаменты»
- **THEN** отправляется `GET /api/v1/sortaments`, а создание отправляет `POST /api/v1/sortaments` с телом `{number,name,standardType,standard,unit}`

#### Scenario: Редактирование и удаление сортамента
- **WHEN** пользователь редактирует и удаляет сортамент
- **THEN** отправляются `PUT /api/v1/sortaments/{id}` с `{name,standardType,standard,unit}` и `DELETE /api/v1/sortaments/{id}` после подтверждения

### Requirement: Ошибки и состояния загрузки справочников
Экраны справочников SHALL отображать состояние «Загрузка…» при получении данных и SHALL показывать человекочитаемые русские сообщения для ошибок `duplicate`, `not_found` и `bad_request` в баннере `.banner-error` без падения приложения.

#### Scenario: Дубликат номера
- **WHEN** создание материала возвращает 409 с кодом `duplicate`
- **THEN** интерфейс показывает русское сообщение о занятом номере и остаётся работоспособным

#### Scenario: Состояние загрузки
- **WHEN** список материалов загружается
- **THEN** интерфейс показывает сообщение «Загрузка…» до завершения запроса
