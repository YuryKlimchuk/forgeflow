# Proposal

## Why

Бэкенд модулей `directories` (материалы и сортаменты) и `technology` (оборудование и технологические процессы) полностью реализован и опубликован через REST (change 21–24), однако во фронтенде ForgeFlow для этих модулей нет ни одного экрана: пользователь не может вести справочники материалов/сортаментов/оборудования и работать с техпроцессами. Настоящий change добавляет React/TypeScript UI поверх уже существующих контрактов, не меняя бэкенд.

## What Changes

- Добавить в шапку приложения (`App.tsx`) два новых раздела навигации — «Справочники» и «Технология», сохранив существующие «Каталог» и «Планы», на тех же state-based принципах без стороннего роутера.
- Раздел «Справочники» — вкладки «Материалы» и «Сортаменты»: список, создание, детальная страница, редактирование изменяемых полей и удаление с подтверждением (`/api/v1/materials`, `/api/v1/sortaments`).
- Раздел «Технология» — вкладки «Оборудование» и «Техпроцессы»:
  - «Оборудование»: список/создание/деталь/редактирование/удаление (`/api/v1/equipment`).
  - «Техпроцессы»: список (номер, наименование, деталь, признак «по умолчанию»), создание с обязательным выбором детали из каталога, детальная страница с операциями, переименование, удаление, добавление/удаление операций (оборудование выбирается `<select>` с пустой опцией «без оборудования»), переключение признака «по умолчанию».
- Расширить `api.ts` типами и клиентами для материалов/сортаментов/оборудования/техпроцессов (все вызовы через `authFetch` + `toJsonOrThrow`) и функциями humanize-ошибок, включая специальный код `invalid_state`.
- Добавить тесты Vitest + testing-library для новых компонентов и API-клиентов по образцу существующих (`App.test.tsx`, `PlanList.test.tsx`, `api.test.ts`).

## Capabilities

### New Capabilities

- `frontend-directories`: веб-интерфейс справочников «Материалы» и «Сортаменты» — список, создание, детальная страница, редактирование изменяемых полей, удаление, типизированные API-клиенты и humanize-ошибки.
- `frontend-technology`: веб-интерфейс «Оборудование» (CRUD) и «Техпроцессы» (список, создание с выбором детали, детальная страница с операциями, привязка оборудования nullable, переключение «по умолчанию»), типизированные API-клиенты и humanize-ошибки, включая `invalid_state`.

### Modified Capabilities

- `frontend-catalog`: оболочка приложения (шапка/разделы/вкладки) расширяется новыми разделами навигации «Справочники» и «Технология» и их вкладками.

## Impact

- Затрагивается только `frontend/src/`: `api.ts` (типы, клиенты, humanize-функции), `App.tsx` (навигация), новые React-компоненты для справочников/оборудования/техпроцессов и новые тесты. При необходимости — `frontend/package.json` без новых runtime-зависимостей.
- Бэкенд, REST-контракты, миграции Flyway, Keycloak и доменная модель не изменяются; новые библиотеки не добавляются.
- Существующие экраны «Каталог» и «Планы» сохраняют поведение; существующие тесты остаются зелёными.

## Non-Goals

- Пагинация и полнотекстовый поиск в списках справочников и оборудования; фильтрация техпроцессов по детали; графические представления.
- Изменение бэкенда, REST-эндпоинтов, форматов запросов/ответов или доменной модели.
- Редактирование уже существующей операции (смена `equipmentId`/`number` существующей операции) — вне объёма; смена оборудования выполняется удалением и повторным добавлением операции.
- Реализация бизнес-инварианта «процесс по умолчанию» на клиенте — клиент только вызывает PUT/DELETE `/default` и показывает ошибку `invalid_state`.
