# Spec Delta

## Purpose

Описывает tenant-scoped HTTP-контракт запуска и чтения расчётов потребностей производства и его поведение при ошибках.

## ADDED Requirements

### Requirement: REST запуска расчёта
REST SHALL предоставлять запуск расчёта потребностей через `POST /api/v1/plans/{planId}/calculations` и SHALL возвращать статус 201 с сохранённым расчётом, включая его идентификатор, ссылку на план, момент выполнения и позиции.

#### Scenario: Успешный запуск
- **WHEN** клиент отправляет POST для доступного плана текущей организации
- **THEN** ответ имеет статус 201 и тело сохранённого расчёта с позициями

#### Scenario: Пустой план
- **WHEN** клиент отправляет POST для плана без элементов
- **THEN** ответ имеет статус 201 и тело расчёта с пустым списком позиций

### Requirement: REST поля позиции расчёта
REST SHALL возвращать для каждой позиции расчёта поля: тип элемента, идентификатор, номер, наименование, количество, вид потребности, единицу и источники; поле `sources` SHALL быть JSON-массивом объектов вида `{"value": "<uuid>"}`, где каждый элемент — идентификатор головной сборки плана, породившей позицию.

#### Scenario: Форма источников
- **WHEN** расчёт содержит позицию с одним источником
- **THEN** поле `sources` равно массиву из одного объекта `{"value": "<uuid>"}` с идентификатором головной сборки плана

### Requirement: REST чтения расчётов
REST SHALL предоставлять список расчётов плана через `GET /api/v1/plans/{planId}/calculations` и чтение одного расчёта через `GET /api/v1/plans/{planId}/calculations/{calculationId}`, оба со статусом 200, и SHALL перед чтением валидировать, что план существует и принадлежит текущей организации.

#### Scenario: Список расчётов
- **WHEN** клиент запрашивает список расчётов доступного плана
- **THEN** ответ имеет статус 200 и содержит все сохранённые расчёты этого плана

#### Scenario: Один расчёт
- **WHEN** клиент запрашивает конкретный расчёт по его идентификатору
- **THEN** ответ имеет статус 200 и содержит данные этого расчёта

#### Scenario: Список для чужого или несуществующего плана
- **WHEN** клиент запрашивает список расчётов несуществующего или принадлежащего другой организации плана
- **THEN** ответ имеет статус 404 и код `not_found`, а не 200 с пустым списком

#### Scenario: Один расчёт для чужого или несуществующего плана
- **WHEN** клиент запрашивает конкретный расчёт для несуществующего или принадлежащего другой организации плана
- **THEN** ответ имеет статус 404 и код `not_found`

### Requirement: REST ошибки расчётов
REST SHALL возвращать статус 404 для отсутствующего или чужого плана либо расчёта, статус 404 с кодом `specification_item_not_found` и идентификатором проблемной ссылки, если спецификация ссылается на отсутствующую или чужую вложенную сборку, и статус 409 с кодом `bom_cycle`, если при расчёте обнаружен цикл вложенности сборок.

#### Scenario: Отсутствующий план
- **WHEN** запрос адресует несуществующий план
- **THEN** ответ имеет статус 404 и код `not_found`

#### Scenario: Чужой расчёт
- **WHEN** запрос адресует расчёт другой организации
- **THEN** ответ имеет статус 404 и не раскрывает данные расчёта

#### Scenario: Dangling-ссылка на вложенную сборку
- **WHEN** при запуске расчёта строка спецификации ссылается на удалённую или принадлежащую другой организации сборку
- **THEN** ответ имеет статус 404 и код `specification_item_not_found` с идентификатором проблемной ссылки

#### Scenario: Цикл BOM
- **WHEN** при запуске расчёта обнаруживается цикл вложенности сборок
- **THEN** ответ имеет статус 409 и код `bom_cycle`

### Requirement: REST совместимость плоской структуры
REST SHALL сохранять существующий контракт `GET /api/v1/plans/{id}/flat` без изменений: статус 200 и массив объектов `number`, `name`, `quantity`, отсортированный по `number`.

#### Scenario: Неизменный контракт
- **WHEN** клиент запрашивает `GET /api/v1/plans/{id}/flat` доступного плана
- **THEN** ответ имеет прежнюю структуру и статус 200 без изменений

### Requirement: REST tenant-контекст расчётов
REST SHALL определять организацию только через серверный `OrganizationContext` и SHALL не принимать tenant из URL, тела или пользовательского заголовка при запуске и чтении расчётов.

#### Scenario: Изоляция запроса
- **WHEN** клиент организации A запрашивает расчёт плана организации B
- **THEN** ответ имеет статус 404 и не раскрывает данные организации B
