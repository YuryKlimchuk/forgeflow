# Proposal

## Why

Строка электронной спецификации может иметь допустимые замены по ГОСТ Р 2.106-2019, но ForgeFlow пока не хранит и не показывает такие варианты. Из-за этого пользователь не может зафиксировать допустимый однотипный заменитель рядом с основной позицией, сохраняя основную позицию дефолтной для расчёта.

## What Changes

- Добавить управление одноуровневыми заменителями строк спецификации: просмотр, добавление и удаление.
- Хранить замены отдельным агрегатом `Substitution`, адресованным организацией, сборкой и основной ссылкой элемента каталога; `SpecificationRow` не изменять.
- Ограничить заменители типами `PART` и `ASSEMBLY`, запретить кросс-тип, самозамену и дубликаты; существование элемента в каталоге при добавлении не проверять.
- Удалять замены каскадно при удалении строки и копировать их 1:1 при копировании спецификации.
- Расширить представление строки признаком `hasSubstitutes`; не включать заменители в `flatten` и расчёт.
- Расширить application/API и REST контракт операциями `listSubstitutes`, `addSubstitute`, `removeSubstitute` с кодами ошибок 404, 409 и 400.
- Добавить в UI звёздочку у строк с заменами, модальное окно со списком и удалением заменителей и форму добавления однотипного `PART`/`ASSEMBLY`.
- Добавить демонстрационные замены в seed-данные спецификаций.

## Capabilities

### New Capabilities

Нет. Функциональность является изменением существующих capability.

### Modified Capabilities

- `specifications`: доменная модель, application-контракт, жизненный цикл замен и признак наличия замен.
- `specifications-rest`: REST-операции управления заменителями и их ошибки.
- `frontend-catalog`: отображение и управление заменителями в `SpecificationDetail`.

## Impact

Изменения затронут доменный и application-код модуля `specifications`, его API и in-memory репозитории, REST-контроллер и обработку ошибок, seed-загрузчик и `seed-data/specifications.json`, а также типизированный frontend API и компонент `frontend/src/SpecificationDetail.tsx`. Новые модули и зависимости не добавляются; межмодульная работа с каталогом использует существующие API `PartService` и `AssemblyService`.

## Non-goals

- Переключение дефолтной позиции строки на заменитель.
- Участие заменителей в `flatten`, расчёте потребностей или рекурсивном выборе замен.
- Саб-домен ВЗК и замены для типов `BUY`, `STANDART` или `VZK`.
- Проверка существования, активности или tenant-принадлежности ссылки заменителя в каталоге сверх существующего правила прямых ссылок спецификации.
