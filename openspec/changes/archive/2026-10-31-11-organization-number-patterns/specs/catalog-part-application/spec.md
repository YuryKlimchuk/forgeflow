# Spec Delta

## MODIFIED Requirements

### Requirement: Создание детали
Сервис деталей SHALL создавать активную `Part` с уникальным в пределах организации номером и SHALL отклонять номер, не соответствующий заданному паттерну организации; при отсутствии паттерна SHALL разрешать любой непустой номер.

#### Scenario: Создание новой детали
- **WHEN** текущая организация установлена и передан запрос с новым `number` и непустым `name`
- **THEN** сервис возвращает `PartView` с сгенерированным `PartId`, переданными `number` и `name`, а `createdAt` и `updatedAt` равны времени создания

#### Scenario: Дублирующий номер
- **WHEN** в текущей организации уже существует активная деталь с переданным `number`
- **THEN** сервис выбрасывает `DuplicatePartNumberException` и новую деталь не создаёт

#### Scenario: Создание детали по паттерну
- **WHEN** для текущей организации задан `PART-[0-9]+` и передан свободный номер `PART-42`
- **THEN** сервис создаёт активную деталь и возвращает `PartView`

#### Scenario: Номер детали не соответствует паттерну
- **WHEN** для текущей организации задан `PART-[0-9]+` и передан номер `42`
- **THEN** сервис отклоняет создание ошибкой клиентской валидации и не сохраняет деталь

#### Scenario: Паттерн детали не задан
- **WHEN** для текущей организации паттерн `Part` отсутствует или пуст
- **THEN** любой непустой номер, не являющийся дубликатом, принимается

#### Scenario: Переименование детали
- **WHEN** у существующей детали меняется только `name`
- **THEN** сервис не проверяет номер по паттерну и сохраняет новое имя
