# Spec Delta

## MODIFIED Requirements

### Requirement: Создание дополнительного типа
Каждый сервис SHALL создавать активную сущность с уникальным в организации номером и SHALL отклонять номер, не соответствующий заданному паттерну организации; при отсутствии паттерна SHALL разрешать любой непустой номер.

#### Scenario: Создание новой записи
- **WHEN** текущая организация установлена и переданы непустые `number` и `name`, а номер свободен
- **THEN** сервис возвращает созданную запись с новым идентификатором

#### Scenario: Дубликат номера
- **WHEN** активная запись того же типа с таким номером уже принадлежит организации
- **THEN** сервис отклоняет создание ошибкой конфликта и не сохраняет новую запись

#### Scenario: Создание Assembly по паттерну
- **WHEN** для организации задан `ASM-[0-9]+` и передан свободный номер `ASM-7`
- **THEN** сервис Assembly создаёт активную запись

#### Scenario: Создание Buy по паттерну
- **WHEN** для организации задан паттерн Buy и передан соответствующий свободный номер
- **THEN** сервис Buy создаёт активную запись

#### Scenario: Создание Standart по паттерну
- **WHEN** для организации задан паттерн Standart и передан соответствующий свободный номер
- **THEN** сервис Standart создаёт активную запись

#### Scenario: Создание Vzk по паттерну
- **WHEN** для организации задан паттерн Vzk и передан соответствующий свободный номер
- **THEN** сервис Vzk создаёт активную запись

#### Scenario: Номер не соответствует паттерну
- **WHEN** номер любого из четырёх типов не соответствует заданному паттерну его типа
- **THEN** соответствующий сервис отклоняет создание ошибкой клиентской валидации и не сохраняет запись

#### Scenario: Паттерн не задан
- **WHEN** паттерн типа отсутствует или пуст
- **THEN** любой непустой номер, не являющийся дубликатом, принимается
