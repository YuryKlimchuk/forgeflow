# Proposal

## Why

ForgeFlow уже предоставляет REST-контракт для управления деталями каталога, но у пользователей нет клиентского интерфейса для просмотра и изменения этих данных. Первый React-фронтенд позволит проверить пользовательский сценарий каталога поверх готового API без изменения Java-бэкенда.

## What Changes

- Добавляется независимое приложение `frontend/` на Vite, React и TypeScript в корне монорепозитория.
- Добавляется экран каталога деталей со списком, созданием, переименованием и удалением деталей.
- Добавляется человекочитаемое отображение ошибок REST API для ответов 400, 404 и 409.
- Добавляется светлая enterprise-стилизация на обычном CSS с CSS-переменными и палитрой RAL 7024/RAL 7032.
- Добавляются обязательные компонентные тесты на Vitest и React Testing Library.
- Java-бэкенд, его REST-контракт и Spring Modulith-модули не изменяются.

## Capabilities

### New Capabilities

- `frontend-catalog`: пользовательский интерфейс для просмотра и управления деталями каталога через существующий REST API.

### Modified Capabilities

- Нет.

## Impact

- Новые файлы и npm-конфигурация в `frontend/`; существующая Java-часть репозитория не изменяется.
- В dev-режиме Vite проксирует `/api` на `http://localhost:8080`; публичный REST-контракт используется без изменений.
- Добавляются зависимости React, Vite, TypeScript, Vitest и React Testing Library в пределах независимого `frontend/`.
- CI/локальная проверка должны уметь устанавливать зависимости, запускать тесты фронтенда и собирать приложение отдельно от Maven-сборки.
