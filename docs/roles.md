# Роли и права доступа

## 1. Общие положения

ForgeFlow — многопользовательская SaaS-платформа. Система поддерживает глобальные роли и роли в пределах отдельной организации (тенанта).

- **Глобальные роли** определяют полномочия пользователя на уровне всей платформы ForgeFlow.
- **Роли организации** определяют полномочия пользователя в рамках конкретной производственной организации.

Роль организации не предоставляет полномочий в других организациях, участником которых пользователь не является.

## 2. Глобальные роли

### SUPER_ADMIN

Глобальная роль администратора платформы ForgeFlow.

Предназначена для управления SaaS-платформой и её организациями.

Полномочия:
- просмотр списка организаций;
- просмотр общего статуса организаций;
- блокировка и разблокировка организаций;
- выполнение административных операций на уровне платформы;
- управление системными настройками, если они предусмотрены продуктом.

`SUPER_ADMIN` не является ролью владельца производственного предприятия.

Доступ к производственным данным организаций не предоставляется автоматически только на основании этой роли.

## 3. Роли в пределах организации

### OWNER — владелец предприятия

Роль владельца конкретной организации ForgeFlow.

Владелец отвечает за управление организацией и обладает административными полномочиями в её пределах.

Полномочия:
- просмотр и изменение настроек организации;
- управление участниками организации;
- приглашение пользователей;
- назначение и изменение ролей участников;
- управление доступом участников;
- доступ ко всем функциональным возможностям организации;
- управление производственными данными организации;
- выполнение административных операций в пределах своей организации.

Владелец одной организации не получает дополнительных прав в других организациях.

В активной организации должен быть как минимум один владелец. Система не должна допускать удаления или лишения полномочий последнего владельца.

## 4. Правила назначения ролей

- Глобальные роли назначаются на уровне платформы.
- Роли организации назначаются отдельно для каждой организации.
- Один пользователь может иметь разные роли в разных организациях.
- Пользователь может состоять в нескольких организациях.
- Назначение `OWNER` в одной организации не предоставляет глобальных полномочий.
- Назначение `SUPER_ADMIN` не означает автоматического включения пользователя в состав всех организаций.
- Операции назначения и изменения ролей должны проверять полномочия инициатора.

## 5. Технические требования

- Keycloak используется для аутентификации пользователей и управления глобальными ролями.
- Членство пользователей в организациях и их роли в организациях хранятся и проверяются в ForgeFlow.
- Backend обязан проверять права доступа при выполнении каждой защищённой бизнес-операции.
- Проверка доступа не должна ограничиваться скрытием элементов интерфейса.
- Доступ к данным проверяется с учётом активной организации и принадлежности данных этой организации.
- Проверки глобальных полномочий и полномочий организации должны быть разделены.
